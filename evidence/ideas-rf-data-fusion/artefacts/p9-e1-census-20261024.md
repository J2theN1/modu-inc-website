## Nano identity (v2 vs v3) — UNSETTLED via reachable routes

`getBaseModelName()` is an ML Kit GenAI **client** call: it can only be made
from inside an app that bundles the GenAI client. The only such app on the
device is PhoneLab, and its current build exposes no invocable entry point
(see Smoke). No shell/app_process route reaches it, and the AICore APK's own
version string does not name the model. **Verdict: not settled in E1.**
Settling path (a build task, outside E1's fence): a PhoneLab probe build
that logs `getBaseModelName()` + feature `checkStatus()` on launch — the
Oct 9 build did exactly this for checkStatus (below), so the pattern is
proven; it is simply absent from 0.4.7-wl1's launch path.

## AICore generate() smoke — NOT EXECUTED: no reachable route on this build

The one smoke call was attempted through the only sanctioned route that
exists on the device and stopped where the route stops:

1. **Route inventory.** ML Kit generate() requires an app-context call.
   Exactly one app bundles the client (PhoneLab, above). AICore's binder
   service is permission-gated (`BIND_SERVICE` permission on
   `AiCoreMultiUserService`) under Restricted Package Binding — the plan's
   §1.4 verdict, re-confirmed by this census's service dump. The on-device
   `ai_worker`'s `generate` endpoint is **not** AICore — its source routes
   generate to LiteRT-LM (Qwen3-0.6B) on the Mali GPU — and its HTTP daemon
   is not listening anyway (only its embed backend on 127.0.0.1:8788 is up).
2. **The attempt.** Captured logcat on the Legion
   (`timeout 45 adb logcat`, 16,695 lines, file `/tmp/e1_logcat.txt` on the
   Legion) and launched PhoneLab's MainActivity:
   `am start -n com.modu.phonelab/.MainActivity` → ActivityTaskManager
   **`result code=3`, LAUNCH_SINGLE_TOP, `wasVisible=true`** — PhoneLab was
   already running in the foreground from an earlier `START_RAW_GNSS`
   session, so no fresh `onCreate` ran and **no GEMINI/checkStatus/generate
   log lines were emitted** anywhere in the capture.
3. **Why it stops here.** The remaining ways to force the probe — force-stop
   and relaunch PhoneLab — would kill its live session mid-work, which is
   outside E1's minimal footprint; and 0.4.7-wl1's package dump shows no
   receiver/service entry point to invoke instead. (Launching the
   `PhoneInspectorActivity` was considered and not used: unknown side
   effects on the live session, and its output is screen-only — no receipt
   this lane could capture.) The estate record shows the route *can* work:
   on Oct 9 a PhoneLab build logged **`GEMINI: checkStatus RESULT=0
   (AVAILABLE)`** on the live P9 (`p9-inference-20261009.md`) — but that
   probe is not in the current build's launch path, and checkStatus was
   never followed by a generate() call in any record.

**Verdict, exactly as briefed:** every route to a first generate() call
from this session requires building/installing an app (a PhoneLab probe
build, or the AICore-mailbox app below) — so the smoke did not run, and
nothing was installed or changed. **generate() has still never been called
on this device.** Consequence per the plan: J3 stays parked until the
probe build exists; the Nano line's price is now precisely "one small
PhoneLab build", not an unknown.
